# 14. 地端啟動與環境 DB 切換

規範地端(本機)啟動後端 API 時,如何選擇要連接的環境資料庫(SIT / UAT),以及 VS Code Spring Boot Dashboard 的使用限制。

---

## 🌐 環境與 DB 實際對應

系統有兩組測試團隊分別在 SIT / UAT 環境測試,**兩環境的 DB 不同、倒入的測試資料也不同**。各環境與 DB 的實際對應:

| 環境 | 後端位置 | Profile | DB(內網位址) | DB(外網位址) |
|---|---|---|---|---|
| SIT 測試環境 | 35.194.171.114(前端 `.env.sit` 指向) | `sit` | 10.109.128.3 / `rdss` | 104.199.162.243 / `rdss` |
| UAT 測試環境 | 34.80.125.220:8080(前端 `.env.uat` 指向) | `uat` | 10.109.128.3 / `rdss_n` | 104.199.162.243 / `rdss_n` |
| 地端開發 | 本機 :8081 | `local` / `localuat` | ——(連不到) | 104.199.162.243 / `rdss` 或 `rdss_n` |

**`10.109.128.3`(內網)與 `104.199.162.243`(外網)是同一台 DB 主機的兩個 IP**:部署在 GCP 內網的 SIT/UAT 後端走內網位址,地端開發者從外部走外網位址,連到的是同一顆資料庫。因此:

- 地端跑 `local` → 連 `rdss` = **SIT 測試團隊使用的同一顆 DB**
- 地端跑 `localuat` → 連 `rdss_n` = **UAT 測試團隊使用的同一顆 DB**

> 佐證:兩位址上的資料庫剛好都是 `rdss` + `rdss_n` 一對、四個 profile 設定檔的 DB 帳號與加密密碼字串完全相同、`10.109.128.3` 為私有網段僅內網可達。(此對應為由設定檔推斷,尚未以 SQL 查證主機內網 IP;若發現地端查到的資料與測試團隊回報不一致,先回頭驗證此假設。)

---

## 🗂️ Spring Profile 與資料庫對照

後端(`rdss_backend_api_new`)以 `--spring.profiles.active` 決定連接的 DB,對應設定檔在 `src/main/resources/application-{profile}.yml`:

| Profile | DB 主機 | 資料庫 | 用途 |
|---|---|---|---|
| `sit` | 10.109.128.3 | `rdss` | SIT 測試環境 |
| `uat` | 10.109.128.3 | `rdss_n` | UAT 測試環境 |
| `local` | 104.199.162.243 | `rdss` | 外網開發機(SIT 資料) |
| `localuat` | 104.199.162.243 | `rdss_n` | 外網開發機(UAT 資料) |
| `rdssuat` | 10.193.15.100 | `rdss` | 內網 UAT 主機 |
| `prod` | 10.193.15.100 | `rdss` | ⛔ 正式環境,**地端禁止使用** |

> ⚠️ `10.109.128.3` 與 `10.193.15.100` 都是**內網主機,地端(外網)連不到**(除非有 VPN)。地端切換 SIT/UAT 資料,實際使用的是外網開發機的兩個 profile:**`local`(SIT 資料,rdss)/ `localuat`(UAT 資料,rdss_n)**。
>
> ⚠️ 各 profile 的 `server.port` 不一致(`local` 8081、`localuat` 8080、`sit`/`uat` 80),地端啟動一律另帶 `--server.port=8081` 覆寫,前端地端設定即以 8081 為準。

## ⚙️ launch.json 設定方式

設定檔位置:**專案所屬工作區資料夾**的 `.vscode/launch.json`。注意 Dashboard 是以「app 所在的資料夾」往上找最近的 `.vscode/launch.json`——若 `C:\IISI\backend_new\.vscode\launch.json` 存在,會優先於 `C:\IISI\.vscode\launch.json` 生效,兩份設定內容應保持一致,避免啟動吃錯設定。

**每個環境建立一組具名 configuration**,以 `args` 指定 profile:

```jsonc
{
    "configurations": [
        {
            "type": "java",
            "name": "RDSS-SIT資料 (local, rdss)",
            "request": "launch",
            "cwd": "${workspaceFolder}",
            "mainClass": "moi.rdss.platform.RdssBackendApiApplication",
            "projectName": "rdss-backend-api-new",
            "args": "--spring.profiles.active=local --server.port=8081",
            "envFile": "${workspaceFolder}/.env"
        },
        {
            "type": "java",
            "name": "RDSS-UAT資料 (localuat, rdss_n)",
            "request": "launch",
            "cwd": "${workspaceFolder}",
            "mainClass": "moi.rdss.platform.RdssBackendApiApplication",
            "projectName": "rdss-backend-api-new",
            "args": "--spring.profiles.active=localuat --server.port=8081",
            "envFile": "${workspaceFolder}/.env"
        }
    ]
}
```

## 🚀 啟動方式(速查表)

| 啟動入口 | 跑哪組設定 | 怎麼換環境 |
|---|---|---|
| Spring Boot Dashboard 播放鍵 | **固定第一組** | 只能去 launch.json 調整兩組設定的順序 |
| Run and Debug(`Ctrl+Shift+D`) | **下拉選單選的那組** | 下拉直接選 → 按綠色播放鍵或 `F5` |

- 綠色播放鍵 = `F5`,同一個動作;下拉選單**只影響下一次按 F5**,不影響 Dashboard 播放鍵。
- **同時只能跑一個**(8081 只有一個):換環境前先停掉正在跑的,停掉方式隨意——Dashboard 停止鍵 / `Shift+F5` / terminal 內 `Ctrl+C` / 直接關掉該 terminal。
- 啟動時若出現 `Port 8081 was already in use`,是前一個程序還沒完全釋放 port,等一兩秒再啟動一次。
- 臨時跑一次另一個環境 → 走 Run and Debug 下拉;接下來一段時間都要測另一個環境 → 改 launch.json 順序讓 Dashboard 播放鍵直接吃它。
- 無論從哪個入口啟動,執行中的 app 都會出現在 Dashboard,可從 Dashboard 停止。

## 🖥️ 前端(rdss_front)地端啟動

- 地端開發用 `--mode dev`,API 位址由 `.env.dev` 的 `VITE_API_BASE_URL_V2=http://localhost:8081/` 指向地端後端(所以後端啟動固定帶 `--server.port=8081`)。
- **Port 衝突**:Vite 預設 5173,若本機還跑著其他專案的 dev server(如 `ai_coding_agent/frontend` 佔住 `127.0.0.1:5173`),瀏覽 `localhost:5173` 會被導到別的專案。此時改用專屬 port 啟動:

  ```powershell
  npx vite --mode dev --port 5180
  ```

  之後固定用 `http://localhost:5180` 開 RDSS 前端。`--port` 只是指令參數,**不落任何檔案、不會進版控**。
  (注意:`npm run dev -- --port 5180` 在 Windows 下參數會被 npm 吃掉而失效,請直接用上面的 `npx vite` 寫法。)
- Dev server 連續跑太久(1~2 天)可能因 Node heap 耗盡而崩潰(`JavaScript heap out of memory`)。長時間掛著的話,啟動前先設 `$env:NODE_OPTIONS = '--max-old-space-size=4096'` 加大記憶體上限;掛掉時重啟即可,不影響程式碼。
- ⚠️ `.env.dev` 是**被 git 追蹤的檔案**——把 API 位址改成 `localhost:8081` 屬於地端暫時修改,**上板前必須確認沒有把這個修改一起推上去**。

## 🚧 Spring Boot Dashboard 的限制(踩雷紀錄)

VS Code 的 Spring Boot Dashboard extension(vscjava.vscode-spring-boot-dashboard)有以下限制,設定時不要踩:

1. **一個專案只會顯示一個節點**,無法像 Eclipse STS 版一樣在專案下列出多組啟動設定讓你選。
2. 播放鍵啟動時,只會取 launch.json 中**第一個** `mainClass` + `projectName` 相符的設定,後面的永遠不會被用到。
3. Dashboard 是把設定物件直接丟給 debugger,**不會解析 `${input:xxx}` 輸入變數**——在 `args` 裡用 `${input:}` 做選單,從 Dashboard 啟動時不會跳出選擇視窗,profile 會變成未解析的字面值,等於沒載入任何環境設定(DB 連線不明)。請勿使用這種寫法。
4. 若相符的設定 `args` 為空(或找不到相符設定),app 會以 `application.yml` 的預設 profile(`local`)啟動,**連到外網開發機 104.199.162.243**,而不是 SIT/UAT。發現連錯 DB 時,先用 `netstat -ano` 對照 app 的 PID 確認實際連線的 DB 主機。

## ⛔ 禁止事項

- 地端啟動一律禁用 `prod` / `rdssuat` 等正式、內網主機 profile。
- 不要為了切環境去改 `application-{profile}.yml` 的 datasource 內容;切環境只透過 launch.json 換 profile。
